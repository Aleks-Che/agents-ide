# Визуальный конструктор графов

Этап 10 добавляет редактор в **Библиотека → Новый шаблон / Конструктор**.
Встроенный пресет сначала копируется в пользовательский шаблон. Любую его
опубликованную версию можно открыть в конструкторе как основу нового черновика.
Исходные версии и снимки Run остаются неизменяемыми.

## Работа с графом

Палитра получает девять типов узлов из `GET /api/schema/nodes`. Холст React Flow
показывает тот же граф, который сохраняет API. Узлы можно перемещать,
дублировать и удалять; удаление убирает связанные переходы. Связи создаются
перетаскиванием портов или через форму, которая также позволяет изменить
концы существующей связи. Обычный узел имеет один выход, Condition — по одному
`true`, `false`, `unknown`. Параллельные выходы блокируются интерфейсом и сервером.

Поля узлов, списки Command, источники CollectContext и операции PlanControl
создаются из серверных JSON Schema. Необязательное поле включается отдельным
флажком. Списки допускают добавление, удаление и перестановку элементов.
Для промптов есть вставка переменных, для условий — рекурсивный редактор AST,
для входов и структурированных результатов — редактор схемы данных.
Условия поддерживают сравнения, `exists`, `all`, `any`, `not`, ссылки и скалярные
константы. На переходе задаются `loop.id`, конечный `max_iterations`, область
счётчика и разрешённые назначения `work.mode/feedback/plan_feedback`.

AgentTask/LLMRequest выбирают direct/group или наследуют роль. Группы
фильтруются по типу, показываются все кандидаты с порядком, параметрами,
профилями/подключениями и назначениями данных. Источник выбора и порядок
переопределения параметров показаны рядом. Смена AgentTask ↔ LLMRequest
сохраняет промпты и удаляет несовместимый выбор модели. При общей роли
создаётся отдельная роль для преобразованного узла; остальные узлы сохраняют
своих исполнителей.

## Черновики, версии и проверки

**Сохранить черновик** отправляет `expected_version`; ответ 409 с
`version_conflict` оставляет локальные правки в редакторе. Можно скачать свой
черновик или явно заменить его актуальным серверным. Закрытие редактора с
несохранёнными правками требует выбора; уход/перезагрузка страницы использует
`beforeunload`.

**Проверить граф** вызывает `/graphs/validate`. Ошибки и предупреждения
отображаются списком с переходом к конкретному узлу/связи, ошибки также
подсвечиваются на холсте. Любая правка делает прежний отчёт неактуальным.
Проверка публикации не заменяет preflight привязки к конкретному проекту.

**Сохранить версию** доступно после сохранения черновика и повторяет серверную
валидацию. Координаты, подписи и `visual` не входят в `execution_hash`. Если
исполнение уже опубликовано, редактор возвращает существующую версию; новая
раскладка остаётся в черновике. Это соответствует уникальности хеша внутри
шаблона. Версия с другим происхождением не используется для обхода provenance:
импорт такого же локального графа требует отдельного пользовательского шаблона.

После публикации можно создать привязку выбранного проекта, настроить её и
запустить из чата. В конструкторе и форме запуска видны версия схемы,
требуемые возможности и границы проверки capability. Готовность реальных
исполнителей определяется существующим preflight, а не наличием формы.

## Перенос и доверие

Экспорт вызывает `/graphs/export` с серверным пересчётом хеша. Импорт ограничен
1 MiB и проходит `/graphs/import`; в черновик попадает только возвращённое
сервером тело с `origin=imported`. Файловые `trusted` и `execution_hash` не
используются как подтверждение.

Все внешние ссылки на группы, профили и подключения явно сопоставляются с
локальными ресурсами, даже при переносе на той же установке. Группы можно
экспортировать/импортировать отдельно; каждый `resource_ref` требует привязки,
в том числе у отключённых кандидатов. Перед применением показываются команды,
аргументы, роли, входы, пути, назначения переходов и все кандидаты с локальными
endpoint/программами. Изменение сопоставления или каталога отменяет отметку
проверки. После сопоставления граф повторно проверяется сервером.

Отметка просмотра импорта не даёт доверия запуску. Для импортированной версии
форма запуска требует отдельного согласия с конкретным `execution_hash`
preflight. Изменение входов, привязки, режима или планового источника делает
прежнюю проверку и согласие неактуальными; сервер повторно сверяет хеш.

## План Council

В форме входного плана запуска можно явно выбрать подтверждённую последнюю
ревизию Council своего проекта/чата. Черновики, неподтверждённые и устаревшие
ревизии не подставляются автоматически. В запрос передаётся `PlanningSource`
с ID, номером ревизии и хешем подтверждения; текст и PlanItem фиксирует сервер.
Ручной ввод входов сохраняется, в том числе через форму по схеме версии.

## Проверки и границы

`frontend/tests/graph-editor.test.ts` проверяет инварианты редактирования,
ссылки и фильтрацию Council; `frontend/tests/e2e/graph-editor.spec.ts` работает
с реальным локальным API и проверяет цикл через UI, сохранение раскладки,
конфликты, импорт групп/графа, схемные формы, изменение пресета и имитационный
Run через настоящий Runner. Браузерный тест Council также проверяет смену
подтверждённой ревизии и повторный preflight.

Автономная запись реальных harness, capability моделей и незакрытый gate MVP
остаются ограничениями этапов 6A/6B/9. Конструктор не снимает эти ограничения.
