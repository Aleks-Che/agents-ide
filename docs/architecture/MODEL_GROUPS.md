# Группы моделей — реализованный контракт этапа 2A

Проверка 14 сентября 2026 года. Миграции `0004_model_groups` и `0005_model_group_review`; актуальная схема БД сверяется readiness API. Этот контракт готовит данные для исполнителя. Выбор модели, retry/fallback, реальные capability и сетевые probe относятся к этапам 3–7.

## Группы и ревизии

Группы глобальны; `(kind, name)` уникально, включая архивные записи. Agent и llm могут иметь одинаковое имя. Группа содержит 1–200 кандидатов и хотя бы одного включённого. Кандидат содержит стабильный ID, нулевую позицию, enabled, точный model_id, params и один профиль agent либо подключение llm. Вложенные группы и повтор пары исполнитель/модель запрещены.

API под `/api/model_groups`:

| Операция | Маршрут |
| --- | --- |
| Список с kind/include_archived | GET `/` |
| Создание | POST `/agent`, `/llm` |
| Чтение | GET `/{id}` |
| Имя/описание | PATCH `/{id}/agent`, `/{id}/llm` |
| Атомарная замена состава/порядка | PUT `/{id}/agent/members`, `/{id}/llm/members` |
| Удаление кандидата | DELETE `/{id}/members/{member_id}` |
| Архивация / копия | POST `/{id}/archive`, `/{id}/copy` |
| Перенос | GET `/{id}/export`, POST `/import` |

Изменение, копирование и архивация требуют `expected_revision`; DELETE/archive передают её в query, остальные — в JSON. BEGIN IMMEDIATE защищает проверку ревизии и запись. Архивация тоже увеличивает ревизию. Неверный тип маршрута даёт 422 до изменения состава. История Run не удаляется.

При PUT клиент может передать ID кандидата для изменения его параметров, модели и позиции. ID обязан принадлежать этой группе. Если ID отсутствует, существующая пара профиль/подключение + модель сохраняет свой ID; новая пара получает новый ID. Перестановка освобождает временные позиции внутри транзакции и не конфликтует с UNIQUE. Ревизия кандидата увеличивается при изменении его позиции или содержания. Копия/импорт всегда получают новые ID. Ссылки существующих кандидатов на архивные ресурсы можно удалить, переставить или отключить; новый кандидат требует активного ресурса.

## Выбор и параметры

`ModelSelection` — объединение трёх строгих вариантов, экспортируемое в OpenAPI и TypeScript:

```json
{"kind":"direct","harness_profile_id":"profile-id","model_id":"exact-model"}
{"kind":"direct","provider_connection_id":"connection-id","model_id":"exact-model"}
{"kind":"group","group_id":"group-id"}
```

Они доступны через `settings.model_selections[role]`, binding, `RunStart.overrides.model_selections` и `node.config.model_selection`. Прямой выбор полностью задаёт исполнителя, ему не нужен дублирующий role_assignments. AgentTask принимает agent, LLMRequest — llm. Одиночный узел без роли использует тот же config.model_selection. Полная проверка Start/End/связности будет добавлена на этапе 3.

Настройки роли разрешаются defaults → версия → binding → Run, затем явный выбор узла. Выбор direct/group на каждом уровне заменяется целиком, кандидаты разных групп не объединяются. Legacy `model_overrides` — тот же канал выбора на своём уровне: более высокий слой удаляет противоположное назначение этой роли. В одном присланном слое пересечение запрещено. PATCH привязки также убирает противоположное сохранённое назначение. Пустая карта означает наследование; чтобы убрать собственные переопределения binding, передаётся пустая карта соответствующего поля.

`role_parameters[role]` наследует отдельные параметры. У кандидатов итог строится независимо: default профиля/подключения → params кандидата → параметры роли → config.params узла. Списки заменяются; вложенное значение одного параметра передаётся целиком. Legacy flat generation defaults профиля поддерживаются. У ProviderConnection пока нет параметров генерации по умолчанию, поэтому его слой пуст. Params не могут задавать credentials, endpoint, модель, инструменты, программу, prompt и разрешения; размер params ограничен 64 KiB. Проверка конкретных поддержанных параметров и значений относится к preflight адаптера.

## Снимок и совместимость

Новые binding/Run отвергают архивную/отсутствующую группу и группу без включённых кандидатов. В `dependencies.model_groups` сохраняется полный порядок и ревизии, включая отключённые позиции. `harness_profiles` содержит копии settings/kind/executable/version всех кандидатов; `provider_connections` — endpoint/protocol/kind/version/opaque secret_reference. Архивный ресурс кандидата сохраняется с причиной unavailable; он не скрывает следующие позиции. Проверка актуальной авторизации не выполняет сетевые вызовы на этом этапе.

`dependencies.nodes[id].candidates` хранит отдельно разрешённые параметры кандидатов узла и parameter_sources. Источник слоя роли уточняется через snapshot.setting_sources. `model_selection_version=1` маркирует полный новый формат зависимостей. Для legacy direct сохраняется исходная семантика без fallback.

Хеш Run/resolve учитывает исходный хеш версии, итоговую конфигурацию и все зависимости. Хеш определения версии хранится в snapshot.pipeline_execution_hash. Правка ресурса или группы меняет хеш нового Run; старый snapshot и повтор старта с тем же idempotency_key сохраняются. `required_features` автоматически получает `model_groups` при публикации версии с группой и при старте с группой из binding/overrides.

0005 сохраняет прежние данные. Снимки из исходной 0004 могли содержать только ID кандидатов, без settings/secret_reference; потерянную историческую конфигурацию нельзя восстанавливать из текущих источников. Такие снимки остаются доступны для истории, но будущий worker обязан отклонять их исполнение как неподдержанные. Новые null-поля выбора не навязываются старым конфигурациям; старые сохранённые optional null принимаются при чтении.

## Импорт, экспорт и следующие проверки

Перенос группы использует schema_version=1.0.0 и required_features=[model_groups]. Определение содержит kind/name/description, порядок и параметры кандидатов с внешним resource_ref. Экспорт не включает настройки профилей/подключений, endpoint, ciphertext, секреты и secret_reference. Импорт получает `definition`, `resource_bindings` (все внешние ref → локальные ID) и необязательное новое name. Отсутствующие ссылки, другая schema/features, неверный тип ресурса и конфликт имени отклоняются атомарно.

Это перенос определений групп. Полный пакет pipeline, разрешение его ссылок на импортированные группы и проверка доверия графу остаются в этапе 3. Возможности worker, отрицательные сценарии fallback и session recovery проверяются по [runtime](RUNTIME_CONTRACTS.md), [машинам состояний](STATE_MACHINES.md) и [контрактам исполнения](EXECUTION_CONTRACTS.md). Неподдержанные параметры не объявляются проверенными только потому, что группа сохранена.
