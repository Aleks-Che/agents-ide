# OpenCode: проверенная часть этапа 6A

Дата ревью: 2026-09-15. Протокол проверен на установленном OpenCode **1.18.30**
по его `/doc` и [официальной документации](https://opencode.ai/docs/server/).
Этап 6A пока не закрыт целиком: разрешён режим **без инструментов**;
реализация пункта плана с записью и полная приёмка MVP ещё не подтверждены.

## Профиль и запуск

Указать абсолютный путь к native `opencode.exe` и
`settings: {"permission_mode": "no_tools"}`. Обёртки `.ps1/.cmd/.bat` не запускаются.
В текущей версии параметры модели, включая effort, требуют отдельного подтверждённого
отображения на OpenCode variant; неподдержанные параметры приводят к ошибке конфигурации.
Direct сохраняет точный `provider/model`; каталог не выбирает замену автоматически.

Preflight и dispatcher запрещают неподтверждённую политику инструментов. Каждая новая
и возобновляемая сессия должна подтвердить `permission=[{permission:"*",pattern:"*",action:"deny"}]`
и точную directory. Контекст передаётся в prompt из подготовленного сервером пакета.
Это не sandbox с разрешённой записью и не основание разрешать автономные изменения.
При неожиданном permission request адаптер отправляет `reject`, сохраняет событие
и возвращает отдельный исход permission; пользовательское одобрение пока не реализовано.

На Run работает не более одного OpenCode server. При смене профиля старое принадлежащее
дерево завершается до запуска следующего. Worker регистрирует процесс как `kind=harness`,
`role=opencode_server` в БД и Windows Job до возобновления процесса. Перед этим проверяются
поколение владельца и идентичность каталога. Запуск и health входят в мониторинг попытки.

Порт динамический, только `127.0.0.1`. После health проверяются владелец слушателя
(root либо потомок собственного Job), directory и версия. Занятый чужой порт не используется;
до трёх попыток запуска с новыми портами допускаются после доказанной остановки своей
предыдущей группы. Пароль Basic auth случайный, обязательный, существует только в памяти.
Записанные URL/PID не используются для attach после рестарта worker.

Окружение имеет минимальный список системных переменных и путей native auth store.
Provider secrets приложения, proxy, `NODE_OPTIONS`, `BUN_OPTIONS` и произвольные `env`/CLI args
не наследуются. Флаги отключают auto-update/share/project config, запуск использует `--pure`.
Профиль не может отключить Basic auth или переопределить hostname через дополнительные args.

## Транспорт и сессии

Сообщение отправляется как `model: {providerID, modelID}`, `parts: [{type:"text",text:...}]`.
Ответ читается из `parts[].text`, `info.error` и строкового `info.finish`.
Вымышленный part `decision` не используется: JSON/verdict/schema проверяет обычный Runner.
Токены и стоимость учитываются только при корректных числовых значениях; отсутствующие
данные не выдаются за нулевую стоимость. Обрыв/`length` не выдаётся за полноценный ответ.

Directory передаётся query-параметром: проверены кириллица и пробелы. Все HTTP-клиенты
используют `trust_env=False`, `follow_redirects=False`; abort следует той же политике.
Тела ответов ограничиваются при чтении потока, а не после загрузки в память.
Лимиты: запрос 2 MiB, HTTP-ответ/совокупный SSE 10 MiB, одно SSE-событие 64 KiB.
Превышение не приводит к бесшумному урезанию evidence и положительному verdict.

Подписка `/event` устанавливается до сообщения, ждёт `server.connected`, разбирает
разбитые UTF-8/CRLF/multiline frames. События чужой session отбрасываются. Delta,
идентификаторы сообщений, tool lifecycle и permission нормализуются через fenced writes.
Reader отменяется и закрывается после попытки; обрыв активного SSE запрещает объявить успех.

Native session ID сохраняется до отправки сообщения; native assistant message ID —
по событию/ответу до завершения попытки. Политика сессий привязана к Run, профилю/кандидату,
роли и scope пункта плана. Между кандидатами native ID не переносится. Допускаются три
продолжения, затем создаётся новая сессия с текущим контекстом/evidence. Смена версии
server также запрещает продолжение старого native ID.

Перед resume выполняется отдельный GET session. Подтверждённый 404 здесь разрешает
новую сессию. **404/429/5xx после отправки сообщения сами по себе не доказывают отсутствие
исполнения** и не разрешают fallback. `info.error` внутри HTTP 200 также не является успехом.
Отказ Basic auth или отказ соединения до отправки имеют отдельный безопасный исход.
Unknown сохраняется для reconciliation; автоматический повтор полезного исполнения запрещён.

Stop вызывает native abort, затем supervisor обеспечивает остановку собственного дерева.
Подтверждённый MessageAbortedError с запретом всех инструментов даёт interrupted, после чего
Run можно продолжить. Stop/resume проверен через команды API и новый Runner/server
с новым паролем и сохранённым native ID. На End, waiting, pause/stop и ошибке server закрывается.

## Каталог и проверка профиля

`POST /api/harness_profiles/{id}/test` действительно запускает собственный временный server,
читает health/directory/catalog и закрывает процесс; сообщений модели не отправляет.
На время запуска транзакция БД закрывается, перед сохранением сверяется версия профиля.
Конкурентное редактирование возвращает version_conflict, не перезаписывая новый профиль.

`GET .../models` возвращает `fresh|stale|unverified`, TTL по умолчанию 900 секунд.
Смена executable/settings сбрасывает каталог и диагностику; ошибка probe не оставляет fresh.
Изменение файлов авторизации самим OpenCode пока обнаруживается только последующим probe/TTL;
каталог никогда не считается доказательством доступа или успешной оплаты запроса.
Миграция 0012 включена в `SCHEMA_REVISION`; пустая/обновлённая БД проходит readiness.
