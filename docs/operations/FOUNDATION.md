# Эксплуатация каркаса

Основные команды и переменные — в [README](../../README.md). Launcher, API, worker и DPAPI запускаются под одним пользователем Windows с загруженным профилем.

| Симптом | Проверка / действие |
| --- | --- |
| `port_unavailable` | Настроить другой `AGENTS_IDE_PORT` для всех служб и Vite; чужой процесс не завершать |
| `service_busy` | Уже работает ручной API/worker или launcher в том же data dir; проверить `status` |
| `startup_failed` | Проверить `logs/launcher.jsonl`, `api.jsonl`, `worker.jsonl`; повтор после устранения причины |
| `status=stale` | PID/время/образ процесса не совпали; `start` создаст новый launcher, чужой процесс не останавливает |
| API доступен, readiness=503 | Исполнитель отсутствует/устарел либо недоступна БД; `system/status` разделяет причины |
| 401 / истёк код | `auth pair-code --rotate`, повторный вход; активный worker продолжает работать |
| 403 в Vite | Сверить точный `AGENTS_IDE_DEV_ORIGIN`, 127.0.0.1 и порт; запускать UI через прокси |
| `secret_unavailable` | Проверить пользователя/профиль DPAPI; ciphertext сохраняется, переносимость не обещается |
| `path_violation` | Использовать отдельный каталог данных на локальном NTFS, без junction/symlink и посторонних файлов |

Логи JSONL ограничены ротацией: до 5 MB на файл и 3 предыдущих файла на роль. Входные тела запросов, cookie, query strings, значения SecretStore и трассировки с входными данными не записываются. `request_id` связывает HTTP-ошибку с журналом.

Штатный heartbeat — каждые 5 секунд; после 15 секунд без обновления worker помечается stale. Один process lock защищает worker даже при недоступности API. Launcher использует отдельный Job для API и worker: при смерти venv-обёртки завершает оставшихся потомков этой роли перед перезапуском, сохраняя другую роль. После 3 неудачных перезапусков — failed; бесконечного crash loop нет.

`stop` отправляет запрос по случайному launch_id, ждёт штатного завершения и закрывает принадлежащие launcher Jobs. Наличие PID само по себе не разрешает завершение процесса. Для ручного запуска применяется Ctrl+C. Reboot, активные Run, backup/restore, GC, installer и автозапуск входят в последующие этапы; их реализация не подразумевается наличием раннего launcher.

Сборка wheel установлена в отдельное чистое окружение и прошла `migrate`. React production-сборка и реальный Playwright-сценарий входа/перезагрузки/отзыва проверены отдельно. CI workflow добавлен; удалённый прогон GitHub Actions в рамках этой работы не запускался.
