Проверен `docs/IMPLEMENTATION_PLAN.md`: восемь открытых составных пунктов.
Функциональный пункт запуска pipeline/одиночного агента закрыт. Семь условий полной

## Исправление структурированных ответов

Runner передаёт `AgentTask.output_schema` адаптеру. Раньше схема проверялась после
ответа, но обычный запуск агента не передавал её в native request. Codex получает
`turn/start.outputSchema`; это проверено strict process fixture на обычном и legacy
выборе профиля, включая отдельную роль reviewer и продолжение сессии.

OpenCode в режиме `native` получает `format.type=json_schema` и `retryCount=0`:
повторными попытками управляет Runner. Установленный OpenCode 1.18.31 возвращает
объект в `info.structured`, а успешное завершение — `finish=tool-calls`. Адаптер
проверяет объект по схеме и передаёт Runner именно его. Совместимый вариант
`info.structured_output` также поддерживается; противоречивые поля, отсутствующий
результат при `tool-calls`, ошибки схемы и `StructuredOutputError` не принимаются
за успех. Исходный envelope сохраняется в существующем архиве native events.

OpenCode реализует этот формат через инструмент `StructuredOutput`. В `no_tools`
сохраняется запрет всех инструментов; схема передаётся текстом в prompt, JSON
проверяет Runner. Структурированный формат не расширяет разрешения профиля.

## Нативные проверки без внешних моделей

[Воспроизводимый probe](../../scripts/probe_native_runtime.py) создаёт временные
workspace, БД, XDG-конфигурацию и локальный Chat Completions provider. Используются
production API, Runner, адаптер и supervisor, настоящий `opencode.exe` 1.18.31.
Fixture provider возвращает только заданный JSON/StructuredOutput, не команды.

- Pipeline: AgentTask implementer → LLMRequest planner → AgentTask reviewer.
- Группа агентов `heavy`: недоступная модель → рабочая локальная модель.
- Группа LLM `flash`: локальный HTTP 401 → успешный кандидат.
- Отдельный запуск только implementer через `single_agent`.
- Обе задачи завершились; три отдельные native sessions, семь попыток,
  три структурированных ответа. Все зарегистрированные процессы завершены.
- Пять локальных provider requests; **0 внешних модельных запросов**.
  Авторизация пользовательских провайдеров не используется.

Переключение проверяется по успешным StepAttempt с `reason=fallback` и ID нужной
группы, а не предполагается по итоговому статусу Run.
[Машиночитаемый результат](../integrations/fixtures/2026-09-19-native-runtime.json).

- [OpenCode provider auth](../integrations/fixtures/2026-09-19-opencode-provider-auth.json):
  настоящий OpenCode, локальный HTTP 401, `provider_unauthorized`, отсутствие
  эффектов и завершение owned processes.

Из корня репозитория, в активированном backend venv:


Путь отчёта должен быть новым. Probe имеет общий deadline 150 секунд и ограничение
числа запросов. Для Windows требуется пользовательская сессия с доступом к DPAPI
и запуску собственных native processes.

## Дополнение: бесплатный OpenCode Zen

По указанию пользователя выполнена внешняя модельная проверка через штатный
провайдер Zen внутри OpenCode. У `opencode/ling-3.0-flash-fin-free` каталог
установленного CLI и [официальные цены Zen](https://opencode.ai/docs/zen/)
подтверждают нулевые input/output/cache цены на дату проверки. Временная
конфигурация разрешает только эту модель и закрепляет её также в `small_model`.
Пользовательские ключи не копируются; отправлены только синтетические задания.

Production pipeline и single_agent завершились: **три настоящих AgentTask**,
три раздельные сессии, три валидных структурированных ответа, agent fallback и
остановка всех процессов. Число внутренних HTTP-вызовов самого OpenCode отдельно
не измерялось и в отчёте обозначено `null`, а не нулём.
[Нативный результат Zen](../integrations/fixtures/2026-09-19-zen-runtime.json).

Прямой HTTP-запрос вне OpenCode получил 403 `FreeTierError`: бесплатный тариф
доступен только внутри OpenCode. Поэтому LLMRequest в данном pipeline остаётся
на локальном синтетическом provider; доступ к внешнему обычному LLM этим не доказан.
Ранее Nemotron 3.5 Lightning Free отвечала, но не завершила первое задание за
300 секунд; успешная приёмка относится к Ling, не ко всем бесплатным моделям.

Воспроизведение, с явным включением внешней бесплатной модели:

```powershell
python scripts/probe_zen_runtime.py --opencode C:\absolute\path\opencode.exe --model opencode/ling-3.0-flash-fin-free --output zen-runtime.json
```

Скрипт повторно проверяет цены в каталоге перед запуском и отказывается от
неподтверждённой бесплатной модели. Обычный `probe_native_runtime.py` по-прежнему
работает полностью локально.

## Регрессии и актуальная семантика

Отдельный прогон `probe_zen_runtime.py --controls` с той же бесплатной Ling проверил
управление через production API во время активного native шага. **Pause → resume**:
`paused → completed`, две записи AgentSession с одним external session ID.
**Stop → resume**: `stopped → completed`, две записи с разными external session ID.
Обе прерванные попытки имеют `interrupted`, продолжения вернули валидный JSON;
все зарегистрированные процессы завершены. Обычный LLM в этом прогоне не вызывался.
[Отчёт controls](../integrations/fixtures/2026-09-19-zen-controls.json).

Это подтверждает pause/stop/resume OpenCode с настоящей моделью и работу без
браузера. Проверка не прерывала запись файла или другое незавершённое внешнее
действие, поэтому B-002 остаётся открытым; полная матрица обоих harness не закрыта.

Браузерные тесты приведены к уже принятому поведению: единое сохранение валидного
шаблона, изменения групп перед следующим запросом, отключённые по умолчанию лимиты,
передача завершившейся ошибки провайдера следующему кандидату. Независимые тестовые
workspace теперь получают собственный Git repository: прежде общий родительский
checkout создавал ложный конфликт резерваций между сценариями.

Эти решения уже внесены в проект до данной проверки. Исторические требования
неизменяемой версии шаблона, замороженных групп и обязательных лимитов не должны
восстанавливаться только ради старых тестов. История Run/snapshot сохраняется;
текущее поведение описано в актуальных контрактах и регрессиях проекта.

Frontend: 159 Vitest; 55 различных Playwright-сценариев проверены (53 успешных
в общем прогоне, два исправленных прошли в повторном наборе из четырёх).
Полный backend-набор из **1065 тестов**, разбитый на три части: **1052 passed,
13 failed**. Найденные ошибки исправлены; итоговые целевые наборы — **30 + 2 passed**,
включая все 13 первоначальных падений, новые JSON-регрессии и четыре сценария
аварии настоящего worker. После исправлений полный набор повторно не запускался;
результаты общего и целевых прогонов учитываются раздельно.
[Сводка проверок](fixtures/2026-09-19-regressions.json).

Ruff, mypy (143 модуля), ESLint, Prettier, TypeScript/Vite и синхронизация серверных
контрактов прошли. Сборка выдаёт прежнее предупреждение о размере JS chunk.

Помимо схемы AgentTask исправлены два обнаруженных дефекта продукта:

- `/bindings/{id}/resolved` исключает отключённые лимиты так же, как preflight
  и создание Run; policy hash совпадает с реально применёнными настройками.
- При recovery до первого шага наличие служебных `loop_limits` не считается
  начатой работой. Отсутствие execution/process подтверждается отдельно.
  Восстановление backup останавливается на `paused`, явный `resume` затем
  запускает граф. Авария worker после claim восстанавливается без повторного вызова.
