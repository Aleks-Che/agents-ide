# Agents IDE

Локальная рабочая область для проектов, чатов, групп моделей и визуальных pipeline.
React-интерфейс обслуживается FastAPI; отдельный Python worker сохраняет работу
в SQLite/WAL и продолжает её без браузера.

Реализованы конструктор, direct/group, preset с PlanItem/Git, Council для LLM и нативных Codex/OpenCode,
наблюдение через SSE и эксплуатационные команды этапа 12. **Полная v1 ещё не
принята:** автономная запись, восстановление незавершённых внешних операций и полная
приёмка реальных моделей остаются открытыми. См. [план](docs/IMPLEMENTATION_PLAN.md),
[приёмку](docs/operations/RELEASE_ACCEPTANCE.md) и [интеграции](docs/integrations/CAPABILITIES.md).

## Установка

Основная среда: Windows x64, локальный NTFS, обычный пользователь с загруженным
Windows-профилем. Проверенная машина: Windows 10 22H2 build 19045. Нужны Python
3.12–3.13, uv (проверен 0.9.15) и Git (проверен 2.39.1.windows.1).
Linux используется для разработки; DPAPI там возвращает `secret_unavailable`.

Архив поставки содержит готовый `frontend/dist`, Python sources, lockfile
и скрипты. Node для запуска такой поставки не нужен. Распакуйте архив и выполните:

```powershell
./scripts/install.ps1
./scripts/agents-ide.ps1 start
./scripts/agents-ide.ps1 auth pair-code
```

`install.ps1` предназначен для новой установки. Для существующих данных используйте
процедуру update с backup из [эксплуатационной инструкции](docs/operations/OPERATIONS.md).

Если выполнение .ps1 запрещено политикой Windows, выполните команды напрямую
из `backend`, не меняя глобальную ExecutionPolicy:

```powershell
uv sync --locked --no-dev
uv run --locked --no-dev agents-ide migrate
uv run --locked --no-dev agents-ide start
uv run --locked --no-dev agents-ide auth pair-code
```

Откройте **http://127.0.0.1:8765**. Код одноразовый, действует пять минут; сессия —
12 часов. Новый код: `auth pair-code --rotate`. Cookie/CSRF/код не передаются в URL.

Для установки из checkout сначала соберите UI (Node 22.12+ в ветке 22, npm 10–11;
проверены Node 22.20.0 и npm 11.10.0):

```powershell
cd frontend
npm.cmd ci
npm.cmd run build
cd ../backend
uv sync --locked
uv run --locked agents-ide start
uv run --locked agents-ide auth pair-code
```

`start` запускает скрытые launcher/API/worker под текущим пользователем.
Ошибки доступны в **Настройки → Журнал приложения**: фильтр по службе и уровню,
подробности и скачивание. По умолчанию показан текущий запуск; прежние ошибки
доступны через **Период → Вся история** с пометкой «Прошлый запуск».
Журнал сохраняется в `%LOCALAPPDATA%/AgentsIDE/logs`
(при `--data-dir` — в `logs` выбранной папки). Даже если сервер не запускается:

```powershell
./scripts/agents-ide.ps1 logs
./scripts/agents-ide.ps1 logs --role worker --level INFO --limit 200
```

Закрытие терминала не завершает их. `status` показывает состояние; `stop`
останавливает принадлежащие приложению процессы. Занятый порт не освобождается
принудительно. Работа после выхода из Windows не обещается. Автозапуск не устанавливается.

## Первый проект и запуск

1. В настройках добавьте LLM-подключение: URL, ключ, модель. Если каталог недоступен,
   введите ID вручную. Ключ нельзя прочитать обратно. Harness устанавливается
   и авторизуется отдельно под тем же пользователем. В **Установленные harness**
   В «Настройки → Агенты» доступны режим доступа и автоодобрение действий.
   Codex поддерживает чтение, запись в проект и полный доступ; при автоодобрении
   запросы подтверждения отключены, выбранные ограничения доступа сохраняются.
   OpenCode в режиме «Как в OpenCode» использует свои инструменты и правила
   разрешений, а автоодобрение подтверждает запросы, сохраняя явные запреты.
   При выключенном автоодобрении запросы на команды и изменение файлов видны в чате.
   В AgentTask можно переопределить настройки отдельно для Codex и OpenCode;
   без переопределения используются общие настройки. Новые настройки применяются
   при новом запуске или перезапуске этапа; обычное продолжение сохраняет настройки запуска.
   Codex и OpenCode находятся автоматически через PATH и стандартные каталоги установки,
   включая npm на Windows. Нажмите на harness: её каталог моделей загрузится автоматически,
   после чего можно выбрать модель по умолчанию. Подключения и авторизация берутся из самой
   harness. Поддержанные версии: [интеграции](docs/integrations/CAPABILITIES.md).
2. Создайте проект с локальной папкой вне data_dir Agents IDE, затем чат.
3. В **Настройки → Группы моделей** создайте группы типа `agent` или `llm`.
   Имена `heavy` и `flash` произвольны: группа содержит упорядоченные модели
   с конкретной harness/подключением. В группе `agent` выберите установленную harness и
   модель из её каталога. Одну harness можно добавить с разными моделями; отдельные профили
   участников создавать не нужно. Модель по умолчанию подставляется для новых участников,
   существующие группы сохраняют свой выбор. Первая подходящая позиция имеет высший приоритет.
   Настройте параметры и отключите ненужные позиции. В параметрах кандидата можно включить
   расписание: 24 часа × 7 дней либо одну общую строку для всех дней. Зелёные часы разрешены,
   серые пропускаются; часовой пояс сохраняется вместе с расписанием. Перед каждым вызовом
   Run и Council проверяют время и при необходимости переходят к следующему кандидату.
   Начатый вызов не прерывается. Кнопка **Сохранить** сохраняет все настройки группы вместе.
4. В **Шаблонах** скопируйте пресет «Разработка с планом» либо создайте граф.
   ПКМ по карточке открывает меню **Создать привязку / Копировать / Редактировать / Удалить**.
   **Редактировать** открывает конструктор. Кнопка **Сохранить** сохраняет граф и автоматически
   обновляет единственную конфигурацию шаблона, сохраняя параметры привязок.
   Истории версий шаблонов нет. Начатые задания сохраняют историю и исходные ответы;
   **Перезапустить этап** применяет актуальные сохранённые настройки моделей, промптов
   и обработки JSON. Изменение связей графа или рабочей области требует нового запуска.
   Сохранение не создаёт новых привязок. При ошибке JSON можно выбрать **Извлечь JSON
   из сохранённого ответа** в решении ожидания и продолжить без повторного запроса к модели.
   Встроенный шаблон редактируется через пользовательскую копию.
   **Создать привязку** в меню шаблона или шапке раздела позволяет выбрать проект и имя.
   В диалоге проекта нажмите **Запустить шаблон**, выберите шаблон проекта и выполните preflight.
   **Добавить шаблон в проект** позволяет создать привязку прямо в окне запуска.
   ПКМ по привязке открывает **Параметры… / Удалить**. Удаление убирает привязку из списка,
   сохраняя шаблон и историю запусков; привязку с активными заданиями удалить нельзя.
   Выбор проекта слева сохраняет открытый раздел «Шаблоны» и показывает его привязки.
   При создании привязки или в **ПКМ по привязке → Параметры… → Рабочий каталог**
   выберите **Изолированная папка (git worktree)**, чтобы запускать один проект
   одновременно из разных диалогов. Каждый запуск получает отдельную ветку
   `agents-ide/run/<run_id>` и папку `<репозиторий>.agents-ide-worktrees/<run_id>`
   рядом с репозиторием. Все агенты, команды и Git-шаги работают в этой папке;
   путь и ветка показаны в диалоге запуска и его подробностях. Нужен корень Git-репозитория
   с коммитом. Worktree начинается с коммита на момент Start; незакоммиченные и
   игнорируемые файлы (включая установленные зависимости) не копируются.
   При продолжении используется та же папка, при новом запуске — новая.
   Worktree и результаты сохраняются после завершения; слияние и удаление выполняются вручную.
   Два изолированных запуска могут работать параллельно; запуск в обычной папке проекта
   сохраняет блокировку общей рабочей папки. Изолированные папки работают параллельно
   с основной папкой проекта. Общего ограничения числа активных запусков нет:
   worker создаёт отдельный поток для каждого готового задания.
   Пользовательский шаблон можно переименовать через ПКМ → **Переименовать**.
   Задайте необходимые входы или выберите подтверждённый Council. Проверьте
   preflight: модели, команды, пути и права. Импорт требует доверия execution hash;
   ошибки блокируют запуск, предупреждение `capabilities_unverified` само по себе не блокирует его.
5. После запуска этапы и сообщения агента появляются прямо в диалоге. Навигация слева
   показывает справа только выбранный этап; при переходе открывается новый этап.
   Одинаковые соседние записи инструментов объединяются со счётчиком вызовов.
   В списке диалогов работающие запуски и советы моделей отмечены индикатором загрузки.
   Для LLMRequest с JSON-ответом в редакторе узла доступна **Обработка JSON-ответа**:
   удаление начальных блоков `<think>…</think>` (также thinking, analysis, reasoning)
   и извлечение единственного JSON-объекта из Markdown или окружающего текста.
   Извлечение самостоятельно пропускает закрытые блоки размышлений; включать
   отдельное удаление таких блоков для него не требуется.
   Обе опции выключены по умолчанию. Исходный ответ сохраняется в артефакте;
   результат по-прежнему должен соответствовать схеме. Незакрытые блоки размышлений,
   повреждённый JSON и несколько JSON-ответов не принимаются.
   Внутри работающего этапа можно отправить уточнение агенту Codex/OpenCode или ответить
   на его вопрос. Сообщение привязано к текущей попытке и не перейдёт другому агенту.
   **⏸ PAUSE** прерывает запрос AgentTask с сохранением сессии и истории инструментов;
   **▶ START** продолжает ту же задачу в той же сессии. Для остальных узлов пауза наступает
   после завершения текущей операции. **■ STOP** останавливает выполнение; после него
   START повторяет незавершённый этап с исходным заданием в новой сессии агента.
   Выполненные изменения файлов сохраняются. После завершения START открывает новый запуск.
   Потеря сессии или недоступность прежней модели показываются как причина ожидания:
   можно восстановить доступ и повторить START либо нажать STOP → START для нового этапа.
   **↻ RESTART** отменяет прежнее выполнение и создаёт новое с первого этапа по текущему
   сохранённому шаблону и исходным входам. Новый запуск ждёт подтверждённой остановки
   прежнего. История сохраняется, файлы проекта не откатываются.
   Правый клик по этапу слева (или **Shift+F10**) открывает **Перезапустить этап**.
   Команда повторяет выбранный AgentTask, LLMRequest, Command или CollectContext
   текущего цикла после подтверждения остановки прежнего исполнителя, затем продолжает
   шаблон. Более ранние результаты сохраняются; выбранный и последующие этапы получают
   новые попытки, а старые ответы остаются в истории. Возврат через операцию с планом
   или Git-коммит недоступен. Изменения файлов при перезапуске не откатываются.
   **Подробности** открывает граф, цикл, PlanItem, попытки, фактическую модель, fallback,
   результаты и историю. Закрытый браузер не влияет на worker.

Запуски по умолчанию выполняются без лимитов времени, числа вызовов, этапов и повторов.
Старые лимиты шаблонов и привязок не останавливают выполнение. У AgentTask и LLMRequest
нет скрытого тайм-аута или ограничения размера успешного ответа; большие результаты
сохраняются полностью и доступны следующим узлам. STOP продолжает прерывать выполнение.
У провайдера остаются собственные ограничения модели; `max_tokens`/`max_output_tokens`
отправляются только при явном указании в параметрах модели. Старые квоты, кроме лимитов
времени, можно включить при обслуживании через `AGENTS_IDE_ENFORCE_EXECUTION_LIMITS=true`.

Лимиты времени узлов, команд, Git и совета не прерывают выполнение, в том числе в старых
сохранённых настройках. Запуск Codex/OpenCode, подключение к модели и ожидание ответа
не имеют таймаута по умолчанию. При занятой SQLite запись ждёт освобождения блокировки;
просроченный heartbeat не отнимает задачу у живого worker. STOP/PAUSE, проверка поколения
владельца и восстановление после завершения worker продолжают работать. Интервалы опроса,
ожидание завершения процессов после STOP и сроки сессий авторизации сохранены.

Текстовый результат агента доступен следующему узлу через
`{{steps.agenttask_1.latest.validated_result.text}}` или `.report` вместо `.text`.
Если результат уже содержит отдельное поле `report`, используется именно оно.

ПКМ по проекту открывает **Переименовать / Удалить из списка**. Удаление сохраняет файлы
на диске и историю проекта; сначала нужно завершить его активные запуски. Контекстные меню
также доступны с клавиатуры через **Shift+F10**.

В **Настройки → Общие** задайте промпт, язык (русский или английский), LLM-подключение,
модель и параметры генерации сообщения коммита. В узле **GitCommit** включите
**Сгенерировать сообщение коммита**; **Собственные настройки генерации** позволяют
переопределить эти значения только для узла. Передаётся diff фактически подготовленного
коммита, а удалённые файлы перечисляются без их содержимого. Пустой diff не вызывает LLM;
ошибка генерации оставляет запуск ожидающим действий и не создаёт коммит.

В **Настройки → Совет планирования** сохраните двух или трёх участников и объединяющую модель.
Можно использовать Codex/OpenCode, LLM и группы. Состав хранится на сервере и подставляется
в новый совет любого проекта; перед запуском его можно изменить.

Полный preset с автономной записью ограничен gates реальных harness. Для реального
сценария используйте разрешённые LLM/Command/CollectContext или подтверждённый режим
harness без инструментов. Simulated Run — явный тестовый режим.

Узлы с группой моделей связаны с общей группой из настроек. Изменения состава, порядка,
параметров и связанных профилей применяются к уже созданным запускам перед следующим
обращением к модели. Начатый запрос заканчивается с прежним выбором. Исходный snapshot
и записи прошлых попыток сохраняются для истории.

При `model_group_exhausted` откройте причины кандидатов, обновите общую группу или
восстановите доступ и явно продолжите Run. Потеря связи с исполнителем после
отправки, невалидный JSON, failed-вердикт и запрос разрешения не разрешают
бесконтрольный fallback.

Подтверждённое исчерпание квоты провайдера переключает AgentTask/LLMRequest на следующую
модель группы. AgentTask через OpenCode также автоматически переходит дальше, если
исполнитель завершил попытку с ошибкой подключения к провайдеру, таймаутом или временной
ошибкой API после собственных повторов. Кнопку **Продолжить** для такого перехода нажимать
не нужно. Если агент уже изменил файлы, его процесс завершается, а следующая модель
получает исходное задание, последние действия и указание продолжить текущую работу.
Изменения в рабочем каталоге сохраняются; переключение восстанавливается и после сбоя
исполнителя. Если доступных моделей больше нет, запуск ожидает действия пользователя.

Для уже остановившегося AgentTask в **Предоставить решение** доступны продолжение в
сохранённой сессии и переход к следующей модели группы. Сохраните выбранное решение,
затем нажмите **Продолжить**: текущий этап и его история сохраняются. При смене модели
в том же OpenCode используется существующая сессия; другому исполнителю передаются
исходное задание, последние действия и текущие файлы. Это работает и для старых ошибок
`unknown_external_result`. Недоступная сессия при продолжении тем же агентом не приводит
к автоматическому повтору задания с начала.

В диалоге и подробностях запуска блок **Циклы** показывает число переходов `loop` и
оставшихся повторов. Кнопки **−**/**+** изменяют остаток этого запуска без прерывания
текущего этапа; исходный шаблон не меняется. При нуле запуск ждёт перед следующим
переходом цикла: добавьте повторы и нажмите **Продолжить выполнение**. Условие может
завершить цикл раньше. Для `scope: item` остаток учитывается отдельно по пункту плана.
Эти явные бюджеты повторов действуют независимо от отключённых общих лимитов времени.

## Обслуживание

Из `backend`:

```powershell
uv run --locked --no-dev agents-ide diagnostics
uv run --locked --no-dev agents-ide backup C:/Backups/agents-001
uv run --locked --no-dev agents-ide verify-backup C:/Backups/agents-001
uv run --locked --no-dev agents-ide update --check
uv run --locked --no-dev agents-ide update --backup-dir C:/Backups/update-001
uv run --locked --no-dev agents-ide --data-dir C:/AgentsIDE-restored restore C:/Backups/agents-001
uv run --locked --no-dev agents-ide pin RUN_ID
uv run --locked --no-dev agents-ide gc
uv run --locked --no-dev agents-ide compact
```

Backup требует новый каталог вне data_dir. `--include-secrets` добавляет DPAPI
ciphertext, привязанный к Windows-профилю. Репозитории не копируются. Restore требует
новый data_dir и сверку checkout перед продолжением. Копирование одного live .db
не заменяет backup. После ошибки записи update/restore gate запрещает запуск
до завершения восстановления; `maintenance-clear` работает только при свободных locks.

Подробно: [stop/resume, backup/update, квоты и диагностика](docs/operations/OPERATIONS.md).

## Конфигурация

Данные: `%LOCALAPPDATA%/AgentsIDE/{db,artifacts,logs,secrets,runtime,temp}`, ACL
текущего пользователя. API/worker/launcher должны работать от одной учётной записи.
`.local/` внутри checkout предназначен только для изолированных тестов.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `AGENTS_IDE_DATA_DIR` | `%LOCALAPPDATA%/AgentsIDE` | Отдельный локальный каталог |
| `AGENTS_IDE_HOST` | `127.0.0.1` | Другие адреса запрещены |
| `AGENTS_IDE_PORT` | `8765` | Порт API |
| `AGENTS_IDE_FRONTEND_DIR` | `frontend/dist` в checkout | Путь к UI; задаётся при установке wheel |
| `AGENTS_IDE_DEV_ORIGIN` | не задан | Точный Origin Vite |
| `AGENTS_IDE_RUN_ARTIFACT_BYTES` | `1073741824` | Квота артефактов Run |
| `AGENTS_IDE_DATA_BUDGET_BYTES` | `10737418240` | Общая квота данных |
| `AGENTS_IDE_DISK_RESERVE_BYTES` | `67108864` | Запас для остановки |
| `AGENTS_IDE_DETAILED_EVENTS_LIMIT` | `100000` | Подробные события Run |
| `AGENTS_IDE_RETENTION_DAYS` | `30` | Срок подробной терминальной истории |

`--data-dir` и `--port` стоят **до** подкоманды. После изменения env перезапустите
службы, чтобы API и worker получили одинаковые настройки.

## Разработка и проверки

Из backend: `uv sync --locked`, затем `uv run --locked agents-ide api` и
в отдельном терминале `uv run --locked agents-ide worker`. Для Vite задайте
API-процессу `AGENTS_IDE_DEV_ORIGIN=http://127.0.0.1:5173`, из frontend выполните
`npm.cmd run dev`. Vite проксирует /api и SSE; поставка работает только через FastAPI.

```powershell
# backend
uv run --locked ruff check src tests ../scripts
uv run --locked ruff format --check src tests ../scripts
uv run --locked mypy src
uv run --locked python ../scripts/generate_contracts.py --check
uv run --locked pytest -q -ra
uv build

# frontend
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e

# корень: архив с готовым UI
backend/.venv/Scripts/python.exe scripts/build_release.py --output .local/agents-ide-release.zip
```

`AGENTS_IDE_LOAD_REPORT` задаёт путь JSON-отчёта нагрузки 100 000 событий.
Реальные model probes расходуют лимиты и запускаются явной командой.
Fixtures и реальные проверки учитываются отдельно в [журнале](docs/IMPLEMENTATION_LOG.md).
